# 制作・計測・次案の改善フロー

## 画面

トップの「制作・改善フロー」から `/workflow` を開く。比較計画・公開済み動画の登録は既存画面を使う。探索、観察、再検証の下書きを区別し、実測が0件でも探索用の下書きを作成できる。下書きは現段階では明示的なテンプレートでありLLMによる完成原稿ではない。

計測許可と次案の自動作成は別の設定で、初期状態はどちらも停止。現在の設定、最後の実行、最後に成功した実測を別々に表示する。API設定済みだけで接続成功とは表示しない。

手動の「今すぐ計測・改善」と、既存 `npm run collector`、常時ワーカーは同じ収集・診断・下書き作成処理を利用する。自動下書きには有効な実測の根拠が必要。同じ根拠の反復実行は同じ下書きIDになり、1計画につき24時間に1件、未完了2件まで。D1のトランザクション内でも許可、上限を再確認する。

## DB更新

既存のレコードは変更せず、`drizzle/0001_learning_loop.sql` の3テーブルを追加する。更新後は新しい収集処理にもこのマイグレーションが必要。

```sh
npm ci
npm run build
npm run db:migrate
npm run dev
```

`db:migrate` はローカルDB向け。リモートDBはバックアップと接続先確認後に、同じSQLマイグレーションをリモートへ適用する。今回のコード変更自体はデプロイ、マイグレーション、秘密情報の設定を行わない。

## 常時ワーカー

`wrangler.learning.example.jsonc` を自分の運用用設定へコピーし、**Webアプリと同じD1**のIDを指定する。別の空DBに向けない。`LEARNING_OWNER_ID` は `/workflow` に表示する自分のID。`YOUTUBE_CHANNEL_ID` は既存設定と一致させる。APIキーとOAuth情報はWranglerのsecretで設定し、Gitへ保存しない。

`LEARNING_ENABLED` と画面の計画ごとの許可の両方が有効な場合だけ、毎分のCronから実行する。HTTPエンドポイントは公開せず404を返す。認証・クォータ等の継続不能エラーは停止し、設定修正後に画面から手動再試行する。既存の計測時刻、欠測、重複ロックを維持する。

この例は単一の利用者・チャンネル専用。一般公開SaaS向けの利用者別OAuth保管や課金機構ではない。ワーカーのデプロイとsecret設定は未実施で、コードが存在することは常時稼働中を意味しない。

## 台本から公開への引き継ぎ

台本を編集・保存・確認後、台本のハッシュ、版、根拠、固定条件を含む制作パッケージを書き出せる。台本を変えると確認済み状態を解除する。台本確認と完成MP4の確認は異なる。

制作パッケージは動画生成ジョブではない。現在は場面画像・ナレーション・字幕への具体化と、既存の `scripts/produce_video.py` を使った映像制作、完成動画レビュー、YouTube Studioでの公開を別途行う。パッケージだけで `renderReady` や公開許可を付けない。

公開動画を既存画面で登録し、同じ比較計画・冒頭案であることを確認して下書きへ関連付ける。これは利用者の確認として記録し、素材の機械的な一致証明と混同しない。関連付け済みの下書きは固定し、次の下書きで変更する。

## 検証と残る範囲

追加テストはゼロと欠測、指標定義、観測時刻、根拠ハッシュ、探索用下書き、制作確認、所有者分離、上限、重複、トランザクションのロールバックを検証する。既存テスト・型検査・ビルドもCIで実行する。

実キーでの取得、リモートD1、常時稼働、数日間の実測、LLM執筆、画像生成、動画生成ジョブとの自動接続、YouTube APIアップロードはこの変更の実証範囲に含まれない。成功率や因果効果を保証しない。
