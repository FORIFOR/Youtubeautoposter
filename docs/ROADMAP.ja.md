# 実装境界と次の段階

この初期実装は「公開済み動画の計測から次作の台本下書きまで」です。既存Launchloomとの互換性は要件に含めていません。

## 次に実データで確認すること

1. APIキーと所有者OAuthを設定し、1本の動画を公開直後に登録。
2. ローカルの収集プロセスを稼働させ、15分・1時間・24時間・72時間の実測を確認。
3. 日別Analyticsのデータが到着して保存されることを確認。
4. A/B各4本が揃うまで優劣を保留し、その後の改善JSONから別エピソードを制作。

現時点では実チャンネルのキー・認可がないため、この一周を実測で達成したとは扱いません。

## 制作処理を差し替える境界

将来の `StoryRenderer` は下書きと固定条件を受け取り、以下を返します。

- 日本語台本、読み上げ対象テキスト、字幕、場面指示。
- 生成した画像・音声と使用したモデル・声・ライセンス情報。
- 完成MP4、そのSHA-256、実際の尺、制作費、修正回数。

初期対応は、Vrewなどで手動制作したMP4のハッシュ登録です。将来は画像・TTS・FFmpeg編集を組み合わせます。映像生成の再試行・予算上限・進捗保存は制作モジュール側に持たせます。

## 投稿と承認

投稿モジュールを追加する際は、タイトル・説明・対象視聴者・完成MP4ハッシュ・公開範囲を含む承認対象を固定します。対象のいずれかが変わったら承認を無効にします。現在の `Draft.status = reviewed` は台本の確認だけで、公開権限を持ちません。

アップロード成功と一般公開を区別し、実動画ID、実際の公開日時、公開状態を確認して初めて計測を起動します。失敗・重複実行・タイムアウト時に動画を二重投稿しない冪等性が必要です。YouTube APIプロジェクトの制約も実運用前に公式仕様で確認します。

## 常時稼働

ローカル版は開発サーバーと毎分の収集プロセスで動作します。オンライン版のDBとは別です。オンラインで24時間稼働させるには、本人限定の認証を保ったスケジューラーを設定し、`collect(ownerId, repository, youtubeClient)` を安全なサーバー環境から呼びます。

Sitesの画面を公開しただけでは定期ジョブは作られません。外部cronのために本人限定アクセスを解除する実装にはしていません。

## 今後必要になった段階で追加

- 字幕・映像との整合チェック、商用利用条件・生成コスト記録。
- 公開済み動画の情報変更や非公開化の再確認と、計測再開のレビュー操作。
- 詳細分析の原レスポンスと更新履歴の保管、視聴の質を考慮した比較ルール。
- データ量増加時のページ分割、長期保管・削除、運用ログの保持期限。
- 収集障害・OAuth失効・割当量超過の通知。

これらは初期実装に含まれていると表示しません。
