# Growth Studio

日本語YouTube動画を、公開 → 計測 → 比較 → 次作の下書きへつなぐアプリケーションです。このリポジトリで新規に実装しています。既存Launchloomや、添付文に記載されたZIPには依存しません。

このプロジェクトの完了条件は、**実動画を複数本公開し、反響を分析し、その結果を動画の修正に反映すること**です。2026年9月13日に[こぐまのポコのおはなし](https://www.youtube.com/channel/UCpaMwN2CdCok70qTw-EdonA)を新規作成し、3本の日本語ショートを一般公開しました。初期値を記録し、9月14日・16日18時ごろの反響確認を設定済みです。24時間・72時間の観測、分析、修正版の制作はまだ完了していません。[進捗](production/pilot.json)と[制作・投稿記録](production/README.md)を参照してください。

## できること

- 日本語の管理画面。架空の8本を使うデモと、保存される実データを明確に分離。
- 投稿前の比較計画：シリーズ・対象・声・尺・画風・キャラクターを固定し、冒頭だけをA/Bで比較。
- YouTubeの公開動画ID・公開日時・チャンネル・尺の確認、完成MP4のSHA-256による素材の関連付け。
- 公開15分・1時間・24時間・72時間・7日後の累積再生数と高評価の収集。欠測をゼロにしない。
- OAuthの読み取り認可と更新トークンによる日別Analytics取得。
- 同条件・同出典・同指標定義の72時間後再生数の中央値を比較。各案4本、差20%以上を再検証候補とする初期設定。
- 観測ID・除外理由・観測事実・不確実性を含む改善JSON。別エピソードの台本下書きへの反映、編集、台本確認。
- SQLite / Cloudflare D1への永続化と利用者ごとの分離。デモの変更は保存しません。
- ローカルの制作スクリプトで、場面画像・日本語台本からVOICEVOX音声、字幕、縦型MP4を生成。初回3本の素材と台本を保存。

初回パイロットの画像・制作スクリプトは従来の手動経路です。追加した `/production` では、LLM台本 → 画像・音声生成 → 字幕付きMP4 → 完成動画の承認 → YouTube APIアップロードを接続しています。生成・送信とも既定は停止。設定と明示的な許可が必要です。[制作ワーカーの導入](docs/PRODUCTION_BRIDGE.ja.md)を参照してください。台本確認と完成MP4の公開承認は別です。

最初の3本は内容の方向性を探る観察です。管理画面のA/B判定に必要な本数や条件を満たしたと扱わず、実測の一覧と不確実性から次の変更を一つ選びます。24本の計画は、その後の拡張案です。

## ローカルで起動

Node.js 22.13以上を使用してください。

```sh
npm ci
npm run build
npm run db:migrate
npm run dev
```

表示されたローカルURL（通常 [http://localhost:5173](http://localhost:5173)）を開きます。デモはキー不要です。「実データ」に切り替えてサインインすると保存できます。ローカル開発のサインインは付属のループバック専用認証です。オンライン版はSitesの本人限定アクセスと認証を使用します。

ローカルデータは `.wrangler/state` に保存されます。消去すると登録データも消えます。`db:migrate` は未適用のマイグレーションだけを順番に適用します。公開版とローカル版のデータベースは別です。

## YouTubeを接続

1. [Google Cloud Console](https://console.cloud.google.com/apis/library) で YouTube Data API v3 と YouTube Analytics API を有効化します。
2. APIキーと、「デスクトップアプリ」形式のOAuthクライアントを用意します。必要なスコープは `youtube.readonly` と `yt-analytics.readonly` です。
3. `.env.example` を `.env` にコピーし、`YOUTUBE_API_KEY`、`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` を設定します。既存の `.env` がある場合は上書きせず必要項目だけ追記してください。
4. 次を実行し、ブラウザーで対象チャンネルの読み取りを許可します。

```sh
npm run youtube:authorize
```

PKCE・state検証付きのループバック認可を行い、`GOOGLE_REFRESH_TOKEN` と `YOUTUBE_CHANNEL_ID` を `.env` に保存します。トークンはターミナルに表示しません。事前にチャンネルIDを指定していた場合、認可先が一致しなければ保存しません。設定後に開発サーバーを再起動してください。

公開動画の統計だけを使用する場合は `YOUTUBE_API_KEY` と `YOUTUBE_CHANNEL_ID` だけでも動作します。Analyticsの設定がない間は日別分析を取得しません。認可トークンは期限に応じて自動更新しますが、失効・認可取り消し・テスト用認可の期限切れの場合は再認可が必要です。

秘密情報は `NEXT_PUBLIC_*`、クライアントコード、Gitに入れないでください。オンライン版の接続情報はSitesのサーバー環境変数として別途設定します。`.env` は自動でオンライン版には送られません。

## 最初の実動画を登録

1. 実データで「比較計画を作成」。同じシリーズ、声、尺、画風、キャラクターを指定します。
2. Aの質問型、またはBの見せ場先行型で動画を作り、YouTube Studioから公開します。
3. 「動画と計測」から公開URL・エピソード・案・完成MP4を登録します。MP4はブラウザーでハッシュ計算するだけで、アップロードしません。256MB超の場合は `shasum -a 256 /path/to/video.mp4` の結果を入力できます。
4. YouTubeから取得したチャンネルと尺が計画に一致し、一般公開されていることを確認して保存します。声や画風などは登録者が一致を確認してください。計画の作成前に公開された動画も記録できますが、事前に計画した比較のサンプルからは除外します。
5. 定期収集を起動します。最初の15分計測に間に合わせるには、公開直後に登録してください。

```sh
npm run collector
```

このコマンドは**ローカル版専用**です。開発サーバーと収集プロセスの両方を動かし続ける必要があります。ブラウザーを閉じても動きますが、Macのスリープ・プロセス停止中は取得できません。毎分、同じ収集APIを呼び、失敗を記録して次周期に再試行します。設定不足・認証エラーは終了して設定修正を促します。`npm run collector -- --once` で1回だけ実行できます。

オンライン版では「今すぐ収集」が使えます。**オンライン版の常時スケジューラーはまだ設定されていません。** 本人限定のSitesに外部cronをそのまま接続する経路は提供していません。常時運用には、`lib/collector.ts` を実行するスケジューラーとオンラインDBへの認証済み接続を別途構成する必要があります。ローカル収集の結果をオンラインDBへ同期する処理も未実装です。

## 計測と比較の仕様

| 公開後 | 取得可能な範囲 | 用途 |
| --- | --- | --- |
| 15分 | 15分〜20分 | 初動の観測 |
| 1時間 | 1時間〜1時間10分 | 初動の観測 |
| 24時間 | 24時間〜25時間 | 同経過時間の観測 |
| 72時間 | 72時間〜74時間 | 比較の主指標 |
| 7日 | 7日〜7日6時間 | その後の観測 |

- 範囲の前は待機、範囲の後は欠測です。遅延分を補間・逆算しません。API応答の完了が期限を超えた場合も欠測です。実際の取得時刻は必ず保存します。
- 同じ動画・計測点はDBの一意制約で固定します。再収集で上書きしたり、複数回の最大値を選んだりしません。
- 素材ハッシュが同じ再投稿は、公開日時・ID順で最初の素材だけをサンプル候補とします。後の投稿でサンプル数を増やしません。
- 未公開・公開情報の変更・異なるチャンネル・対象・言語・形式・声・画風・キャラクター・尺の範囲違いは比較から除外します。
- 主指標はData APIの `statistics.viewCount`。指標定義は `youtube_data_v3:viewCount:2025-03-31` として保存します。詳細分析やデモの値とは混ぜません。
- 相対差の分母が0なら増加率を計算せず、判断保留にします。4本・20%は検証運用の設定であり、統計的有意差や因果関係の根拠ではありません。
- Analyticsは太平洋時間の日別集計です。遅延を考慮して当日から3日前まで、公開日から7日後までの範囲を取得します。少なくとも6時間間隔で日別値を再取得し、遅れて届く修正を反映します。定期再取得は公開14日後まで、古い動画も登録後に一度取得します。返らない日はゼロとして生成しません。
- 視聴率は完視聴者の割合ではありません。エンゲージビューや視聴時間は日別表に保存しますが、現時点では採用候補の主判定には使いません。
- 収集の重複起動はDBの期限付きロックで抑制します。1回の収集作業には時間予算を設け、残りは次周期に回します。

## 検証

```sh
npm test
npm run typecheck
npm run build
```

テストは比較の誤判定、欠測、時刻境界、重複、定義混在、OAuth更新、Analytics列対応、API失敗、競合収集を検証します。ネットワークはテスト用応答に置き換えています。実チャンネルでの認可・数日にわたる実測の成功を意味しません。

## 構成

- `app/studio.tsx` — 日本語の管理画面、デモ、登録フォーム、台本編集。
- `app/api/` — 本人認証付きの保存・収集API。書き込みは同一オリジンのJSONに限定。
- `lib/growth.ts` — 比較・計測時刻・改善JSON・下書きの純粋なドメイン処理。
- `lib/youtube.ts` — 公式API、更新トークン、日別Analyticsの解析。
- `lib/collector.ts` — 欠測処理、定期収集、再試行、重複起動抑制。
- `db/schema.ts`, `drizzle/` — D1スキーマとバージョン管理されたマイグレーション。
- `scripts/` — 認可・ローカル収集・DB準備・検証。
- `scripts/produce_video.py`, `production/` — 初回3本の台本・画像・音声付きMP4制作と進捗。
- `docs/GOAL.ja.md` — 実投稿、反響分析、修正版の制作までの完了条件。
- `docs/PILOT_24.ja.md` — 最初の24本の段階的な試験計画。
- `docs/ROADMAP.ja.md` — 次段階の制作・投稿機能と接続境界。

React 19 / TypeScript / Vinext / Cloudflare D1を使用しています。付属のSitesビルド処理とUIプリミティブを維持しています。

## AI台本・動画制作・承認後アップロード

`/workflow` の「AI台本・動画制作」から `/production` を開きます。1〜6場面の画像・音声を生成し、FFmpegで1080×1920のMP4へ合成します。映画的な動画生成モデルではなく、生成画像と音声・字幕の合成です。設定済みのモデルだけを使用し、プロンプト内のURLや命令は実行しません。生成原稿は要事実確認、完成動画は要映像・音声レビューです。

完成MP4と公開内容のハッシュに結び付いた24時間の承認後にだけアップロードできます。中断時は保存済みセッションを照合し、結果不明の新規投稿を自動再送しません。一般公開・処理完了をAPIで確認した動画だけ、計測へ登録します。非公開を公開済みとは表示しません。

実プロバイダーでの生成・課金、実チャンネルへの投稿、リモートDB/R2/ワーカーの運用は、回帰テストとは別の導入確認です。[必要設定と運用条件](docs/PRODUCTION_BRIDGE.ja.md)を確認してください。
